# FullKMPExample

This is a Kotlin Multiplatform project targeting Android, iOS, Web.

* [/composeApp](./composeApp/src) is for code that will be shared across your Compose Multiplatform applications.
  It contains several subfolders:
  - [commonMain](./composeApp/src/commonMain/kotlin) is for code that’s common for all targets.
  - Other folders are for Kotlin code that will be compiled for only the platform indicated in the folder name.
    For example, if you want to use Apple’s CoreCrypto for the iOS part of your Kotlin app,
    the [iosMain](./composeApp/src/iosMain/kotlin) folder would be the right place for such calls.
    Similarly, if you want to edit the Desktop (JVM) specific part, the [jvmMain](./composeApp/src/jvmMain/kotlin)
    folder is the appropriate location.

* [/iosApp](./iosApp/iosApp) contains iOS applications. Even if you’re sharing your UI with Compose Multiplatform,
  you need this entry point for your iOS app. This is also where you should add SwiftUI code for your project.

* [/shared](./shared/src) is for the code that will be shared between all targets in the project.
  The most important subfolder is [commonMain](./shared/src/commonMain/kotlin). If preferred, you
  can add code to the platform-specific folders here too.

* [/webApp](./webApp) contains web React application. It uses the Kotlin/JS library produced
  by the [shared](./shared) module.

### Build and Run Android Application

To build and run the development version of the Android app, use the run configuration from the run widget
in your IDE’s toolbar or build it directly from the terminal:
- on macOS/Linux
  ```shell
  ./gradlew :composeApp:assembleDebug
  ```
- on Windows
  ```shell
  .\gradlew.bat :composeApp:assembleDebug
  ```

### Web App

The web application lives in [/webApp](./webApp) and is built with React + Vite.
The shared business logic comes from the Kotlin/JS package generated by [/shared](./shared).

Before using the web app, install [Node.js](https://nodejs.org/en/download) (which includes `npm`).

### Web Development Build and Run

To run the web app in development mode:

```shell
npm run start:web:dev
```

This command:
- generates the Kotlin/JS `developmentLibrary` from `shared`
- points the root npm workspace to that generated package
- installs npm dependencies
- starts the Vite development server

Open the local URL printed by Vite, typically `http://localhost:8080`.

Use this mode when you want hot reload and a local development server.

### Web Production Build

To generate the production web bundle:

```shell
npm run build:web:prod
```

This command:
- generates the Kotlin/JS `productionLibrary` from `shared`
- points the root npm workspace to that generated package
- installs npm dependencies
- runs `vite build`

The production output is generated in:

```text
webApp/dist/
```

This folder contains the static files for deployment, including:
- `index.html`
- `assets/*.js`
- `assets/*.css`

Deploy the contents of `webApp/dist/` to Apache, Nginx, S3, a CDN, or any other static hosting server.

### Test the Production Bundle Locally

After generating the production bundle, you can serve it locally with:

```shell
npm run serve:web:dist
```

This starts a simple local HTTP server for `webApp/dist/` on:

```text
http://localhost:8080
```

To use a different port:

```shell
./scripts/serve-web-dist.sh 9090
```

Use this mode to validate the generated production files before deploying them.

### Web Build Notes

This project does not publish the `shared` package to an npm registry. Instead, the root `package.json`
declares the generated Kotlin/JS package as a local npm workspace, and `webApp` depends on the local
version `shared@1.0.0-SNAPSHOT`.

Important:
- `webApp/package.json` references `shared` as version `1.0.0-SNAPSHOT`.
- The root `package.json` workspace is switched automatically between `developmentLibrary` and `productionLibrary` by the helper scripts in `package.json`.
- If the `shared` module changes, rerun the corresponding web command so the Kotlin/JS distribution and npm workspace stay aligned.
- For CI or internal deployment, use `npm run build:web:prod`.

Server structure for web builds:

On a build server, keep the project structure with the generated `shared` package available locally:

```text
FullKMPExample/
├── package.json
├── package-lock.json
├── node_modules/
├── webApp/
│   ├── package.json
│   ├── src/
│   ├── public/
│   └── dist/
└── shared/
    └── build/
        └── dist/
            └── js/
                └── developmentLibrary/ or productionLibrary/
                    ├── package.json
                    ├── shared.mjs
                    ├── shared.d.mts
                    └── ...
```

Notes:
- A build server needs the root `package.json`, the `webApp` folder, and the generated `shared/build/dist/js/...` folder.
- A static hosting server does not need the full project structure after the build is finished. In that case, deploy only `webApp/dist/`.

To build and run the development version of the iOS app, use the run configuration from the run widget
in your IDE’s toolbar or open the [/iosApp](./iosApp) directory in Xcode and run it from there.
